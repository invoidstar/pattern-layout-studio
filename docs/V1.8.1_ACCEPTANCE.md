# Pattern Layout Studio V1.8.1 Acceptance

Date: 2026-09-27

## Requirement

Uploaded drawings must be filtered before the extraction workflow unless their pixel dimensions match one of the supported drawing formats.

Accepted dimensions:

- 3500 × 3500
- A4 landscape: 2970 × 2100
- A4 portrait: 2100 × 2970

## Preflight gate

- [x] all selected files are dimension-preflighted before source extraction begins
- [x] invalid-size images do not enter background estimation
- [x] invalid-size images do not enter text filtering / OCR
- [x] invalid-size images do not enter morphology
- [x] invalid-size images do not generate parts
- [x] invalid-size images do not participate in page packing
- [x] valid images continue normally in a mixed upload batch

## User notification

- [x] invalid-size images trigger a modal notice
- [x] the notice lists filename and actual pixel dimensions
- [x] the notice states the accepted drawing dimensions
- [x] mixed batches explain that invalid drawings were filtered while valid drawings continue
- [x] all-invalid batches explicitly state that the downstream workflow is blocked
- [x] the upload control also shows the accepted size requirements before selection

## Multi-image behavior

Example:

```text
A.png 3500×3500      -> valid
B.png 1920×1080      -> filtered
C.png 2970×2100      -> valid
D.png 2100×2970      -> valid
```

Expected project:

- A, C and D continue into extraction
- B is reported and excluded
- only A/C/D parts enter the unified page pool

## Defensive validation

The same size assertion remains inside the single-source extraction function even after batch preflight. This prevents unsupported dimensions from entering the image-processing pipeline if that function is reused directly later.

## Regression gates
