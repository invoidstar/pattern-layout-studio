# Pattern Layout Studio V1.3 Implementation

Date: 2026-09-27

## Goal

V1.3 removes the single-page limitation from Pattern Layout Studio.

Before V1.3, MaxRects could only produce one output canvas. Parts that did not fit on that page were marked as `overflow`, which blocked normal export even when every individual part was small enough to fit on its own page.

V1.3 changes the layout model to automatic multi-page packing.

## Pipeline

```
Upload
 -> V1.2 text filtering / smoothing
 -> extracted no-scale parts
 -> MaxRects page 1
 -> remaining parts
 -> MaxRects page 2
 -> ...
 -> Canvas page editor
 -> current-page PNG or all-pages ZIP
```

## Packing V3

File: `src/core/packing.ts`

New API:

- `PackedPage`
- `MultiPagePackingResult`
- `packIntoMultiplePages()`

The algorithm repeatedly runs the existing MaxRects V2 solver. After each pass:

1. successfully placed parts are assigned to the current page;
2. only unplaced parts continue to the next page;
3. iteration stops when all parts are placed or no remaining part can be placed.

### Dedicated-page fallback

A part may physically fit inside the target canvas while failing the normal packing pass because the regular inter-part / edge gap is reserved.

V1.3 distinguishes this from a true oversize part.

If:

```
part.width <= canvas.width
part.height <= canvas.height
```

the part receives a dedicated page and is centered without the artificial packing gap.

Only a part whose own dimensions exceed the target canvas is now considered truly unplaceable.

## Page metadata

`PatternPart` now carries `pageIndex`.

The App keeps the complete part collection while the Canvas Editor renders only the current page.

The page count is derived from placed part metadata, so Undo/Redo still works on the complete project state.

## Canvas editing

All V1.2 editing tools remain available per page:

- select / multi-select
- drag
- lock / unlock
- brush / eraser
- merge / split
- delete
- Undo / Redo

Page navigation clears transient selection/paint/drag state to avoid accidental cross-page edits.

The **重新自动分页** action repacks the complete part set and compacts it back into consecutive pages.

## Export

File: `src/core/export.ts`

### Current page

Exports one PNG:

`pattern-layout-p01-2970x2100-300dpi.png`

or the equivalent 3500x3500 form.

### All pages

All layout pages are independently rendered to PNG, retain the configured DPI metadata, and are packaged into one ZIP using `jszip`.

Example:

```
pattern-layout-03pages-2970x2100-300dpi.zip
  pattern-layout-p01-2970x2100-300dpi.png
  pattern-layout-p02-2970x2100-300dpi.png
  pattern-layout-p03-2970x2100-300dpi.png
```

## No-scale invariant

V1.3 does not solve overflow by resizing.

Across segmentation, pagination, manual editing and export:

- part width is unchanged;
- part height is unchanged;
- only page assignment and x/y placement change.

## UI

The editor now shows:

- total page count;
- current page number;
- previous / next page controls;
- number of parts on the current page;
- `重新自动分页`;
- `当前页` PNG export;
- `导出全部页 ZIP`;
- a warning only for truly oversize parts.
