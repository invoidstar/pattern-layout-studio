# Pattern Layout Studio V1.8 Implementation

Date: 2026-09-27

## Goals

V1.8 is a maintainability release.

The user-visible workflow remains the V1.7 multi-image project experience, while the codebase is reorganized around explicit responsibilities:

- application orchestration
- reusable UI components
- domain models
- vision algorithms
- layout algorithms
- export algorithms
- end-to-end feature workflows

A small Busuanzi traffic widget is also added to the deployed footer.

## Before V1.8

The repository had accumulated most application behavior in:

- one very large `src/App.tsx`
- a flat `src/core/*` directory
- one root stylesheet
- a root types module

That structure worked, but it made ownership of new changes less obvious.

## Core refactor

The previous flat core modules were moved into three algorithm namespaces.

### Vision

`src/core/vision/`

Owns:

- background estimation
- segmentation
- morphology
- contours
- alpha generation
- text filtering
- OCR adapter

### Layout

`src/core/layout/`

Owns:

- MaxRects
- page compaction
- conversion / centering
- no-scale fit validation

### Export

`src/core/export/`

Owns:

- PNG DPI metadata
- page rendering
- ZIP generation

The legacy flat core files were deleted after the new entry path passed a production build.

## Feature layer

Algorithms are composed into workflow modules instead of being assembled directly in the UI.

### Extraction

`features/extraction/process-source.ts`

Processes one source image and returns:

- extracted parts
- source provenance
- diagnostics
- debug previews

### Project

`features/project/build-project.ts`

Owns the multi-image project workflow:

- sequential source processing
- partial failure isolation
- source aggregation
- global part pool
- unified multi-page packing
- aggregate diagnostics

### Layout

`features/layout/`

Owns project-specific layout orchestration above raw packing:

- project-wide page layout
- manual-page validation
- page-index normalization

### Provenance

`features/provenance/source-regions.ts`

Owns safe source-region cloning, lookup and union behavior.

## UI decomposition

The previous monolithic JSX tree was split into:

- `CommandBar`
- `SourcePanel`
- `CanvasPanel`
- `InspectorPanel`
- `TrafficStats`

`app/App.tsx` remains the state/action orchestrator rather than also owning every visual panel.

## Domain layer

Shared structures moved from `src/types.ts` to `src/domain/types.ts`.

This makes domain data explicit and keeps it independent from UI components.

## Traffic widget

`components/TrafficStats.tsx` renders Busuanzi's required IDs:

- `busuanzi_site_uv`
- `busuanzi_site_pv`

The official Busuanzi V3.6.9 script is lazy-loaded after the React footer mounts:

```text
https://cdn.busuanzi.cc/busuanzi/3.6.9/busuanzi.min.js
```

The counter is intentionally isolated from image processing and project state.
