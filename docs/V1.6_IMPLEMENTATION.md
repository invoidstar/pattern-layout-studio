# Pattern Layout Studio V1.6 Implementation

Date: 2026-09-27

## Goals

V1.6 addresses three workflow limitations:

1. users could not explicitly move parts between pages;
2. automatic pagination stopped after greedy per-page packing;
3. controls were visually distributed and page management was inconvenient.

## 1. Cross-page transfer

File: `src/App.tsx`

New flow:

```
selected parts
 + target-page existing parts
 -> fresh MaxRects validation
 -> accepted only if all items fit
 -> target-page repack
 -> source-page repack
 -> empty-page removal
 -> page-index normalization
```

The operation is undoable because a project snapshot is pushed before modification.

Target options include:

- any existing page
- a new page
- previous page shortcut
- next page shortcut

No width / height is changed.

## 2. Global page compaction

File: `src/core/packing.ts`

New API:

- `compactPackedPages()`

It runs after the normal multi-page solver.

### Phase A — whole-page merge

For every later/earlier page pair, combine the item sets and run a complete MaxRects validation.

If all items fit, the pages are merged and page indexes are normalized.

### Phase B — individual backfill

When whole-page merge is impossible:

- sort later-page parts from small to large
- try each part against earlier pages
- run a fresh MaxRects solve for the destination page
- repack the source page after removal
- accept only when both pages remain valid

This continues until no accepted change is found or the safety guard is reached.

## 3. Packing spacing

The UI maintains a `packingGap` state.

Range:

- minimum: 4 px
- maximum: 32 px
- default: 16 px
- step: 2 px

All automatic pagination, page compaction and manual target-page validation use the same gap value.

## 4. Utilization metrics

A per-page summary is derived from live part state:

- part count
- used bounding-box area
- target canvas area
- utilization

Overall utilization is:

```
sum(page part bounding areas)
/
(page count × target canvas area)
```

These metrics update immediately after page transfers.

## 5. UI architecture

V1.6 preserves the Source / Canvas / Inspector three-pane concept but reorganizes controls.

### Command bar

A compact sticky command bar contains:

- upload
- text controls
- edge / split controls
- target / export

### Page strip

The Canvas panel contains a horizontal clickable page strip.

Each chip contains:

- page number
- part count
- utilization percentage

### Inspector

The Inspector places page-management operations before diagnostic information:

- target-page selector
- Move action
- Previous / Next page shortcuts
- packing-gap slider
- global optimization action
- quality grid
- part list

Responsive breakpoints collapse the layout progressively for smaller screens.

## 6. Safety / invariants

Every automated or manual cross-page placement is validated through the same no-scale MaxRects solver.

V1.6 retains:

- exact shape masks
- source contours
- internal RGB preservation
- no scaling
- PNG DPI metadata
- multi-page ZIP
- repair editor
