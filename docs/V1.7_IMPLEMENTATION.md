# Pattern Layout Studio V1.7 Implementation

Date: 2026-09-27

## Goal

V1.7 allows one upload action to contain multiple source images and treats all extracted parts as one layout project.

## 1. Source model

A project now maintains:

- `sourceReferences[]`
- `activeSourceId`

Each source reference contains:

- stable project-local source ID
- original image data URL
- filename
- original width / height
- detected background colour
- per-source debug previews

Each automatic `PatternPart` contains:

- `sourceId`
- exact part image
- exact source contour metadata
- `sourceRegions[]`

## 2. SourceRegion

`PartStats.sourceRegions` stores provenance without mixing coordinate systems.

Each region contains:

- `sourceId`
- optional source-space bounding box
- optional exact source-space contours

Legacy single-source fields are retained for compatibility, but the UI and merge logic prefer `sourceRegions`.

## 3. Sequential batch processing

`processFiles(files)` resets the existing project and then processes files sequentially.

For each source:

`processSourceFile(file, index, total, batchId)`

runs the complete V1.6 extraction path:

- background estimation
- text filter
- optional OCR
- morphology
- exact component labels
- host-aware grouping
- exact local mask extraction
- original RGB preservation
- exact source contour generation

Sequential processing avoids several large ImageData / label buffers existing at the same processing stage.

## 4. Unified packing

Per-source processing returns unplaced parts.

Only after all successful sources finish:

```
allParts = source1.parts + source2.parts + ... + sourceN.parts
```

The complete set is sent into:

`arrangePartsAcrossPages(allParts, target, packingGap)`

once.

Therefore page boundaries are independent of source-image boundaries.

## 5. Aggregate diagnostics

Project-level quality metrics aggregate the successful sources:

- part count: sum
- text-region counts: sum
- raw components: sum
- merged decorations: sum
- morphology counts / pixels: sum
- threshold / spread / foreground ratio: average
- packing diagnostics: final unified page solver

## 6. Source browser

The Source Trace panel contains a thumbnail strip when more than one source is loaded.

Selecting a normal part automatically switches to the correct source.

For a part with multiple source regions, the currently active source remains stable as long as it is one of the part's provenance sources.

## 7. Merge / split provenance

Merge concatenates the selected parts' `sourceRegions`.

If all selected parts share one source, legacy source box / contour fields are also kept.

If several source images contribute, no invalid union box is generated across coordinate systems.

Split refines provenance when the parent maps to exactly one source region. Otherwise it conservatively preserves the parent's multi-source regions.

## 8. Failure policy

Each source is isolated in its own try/catch.

- one source can fail without losing successful sources
- all-successful parts still enter unified packing
- the full operation fails only if zero source images succeed

## 9. Retained invariants

- no part scaling
- exact shape masks
- internal colour preservation
- global page compaction
- cross-page editing
- current-page PNG
- all-pages ZIP
- DPI metadata
